# 限制与路线

[English](Limitations-and-Roadmap) · **中文**

这个库不做什么，直说。这页上的东西都不是藏在脚注里的；如果有哪条限制会让你意外，它就属于这页。

## 缺失的能力

### 跨进程续传

**最大的缺口。** 暂停和续传在同一个进程内有效，但完成度位图只在内存里，磁盘上没有任何东西记录「哪些分片到了」。进程崩溃、被杀、或只是正常退出之后，新进程会从头下 —— 哪怕磁盘上正躺着一个装满正确字节的 `.part` 文件。

对大文件这代价很高：下到 90% 丢掉，等于把 90% 重新拉一遍。

需要什么才能做：在 `.part` 旁边放一个记录位图与 validator 的附带文件，随分片完成写入，再加上「资源是否已变更」的检查。目前未实现。

### 带宽限速

没有限速。下载会吃掉网络和连接预算允许的全部带宽。对桌面应用或共享网络来说，这往往是最先想要的功能。

需要什么才能做：管理器级共享的令牌桶，在两条传输路径的读取边界上施加。

### 内容校验

没有摘要校验环节。库只检查字节数与服务端声明的一致，仅此而已。需要确认内容正确，请在 `Wait` 返回后自己算哈希。

需要什么才能做：一个期望摘要的选项，在完成、改名之前校验。

### User-Agent 选项

没有专门的选项，用请求头：

```go
muyuan.WithHeader("User-Agent", "my-service/1.0")
```

默认是 Go 的 `Go-http-client/1.1`，有些服务端会因此限速或拒绝。做成一级选项是个小改动，但还没做。

### 从环境变量读代理

不读 `HTTP_PROXY`、`HTTPS_PROXY`、`NO_PROXY`。代理只能显式配置，管理器级或任务级。这是刻意的 —— 隐式行为更难推理 —— 但与大多数 Go HTTP 客户端的做法不同。

### 两个独立的危险开关

`WithAllowUnsafeHosts` 把主机校验整个关掉。它做不到「放行环回上的代理，同时仍然拒绝私网目标」，因为两个校验共用一个开关。见[代理与安全](Proxy-and-Security-zh)。

## 会让人意外的行为

这些都有文档，但值得在这里再列一次。

| 行为 | 原因 |
| --- | --- |
| `Workers` 报告分配量，不是实际连接数 | 调度器给的是数字；引擎按文件能切出的片数开连接 |
| 只有 1 条连接的任务完全不发 `Range` 请求 | 单连接走的是单连接路径，整文件流式下载 |
| 分片模式下 `.part` 文件是完整大小 | 预先创建、原地填充 |
| `Downloaded` 会滞后于传输 | 它只统计已完成片，最多落后「每条连接一片」 |
| 很短的下载没有进度事件 | 进度节流到每 200ms 一条 |
| `Wait` 会在排队中和暂停中的任务上阻塞 | 这两种都不是终态 |
| 404 不重试 | 只有 5xx、408、425、429 算瞬态 |
| 对失败任务调 `Resume` 会从磁盘继续 | 这正是设计好的重试途径 |

## 工程层面的缺口

### 测试不在版本库里

模块有 87 个测试 —— 传输引擎 56 个、管理器 24 个、主机校验 6 个、文件名 1 个 —— 包含并发压测和 CI 里的 race detector 运行。**但它们没有被提交。** 仓库的 `.gitignore` 排除了 `*_test.go`，所以克隆下来没有任何测试，CI 的测试步骤会报 "no test files" 然后空转过关。

这是一个已知的、刻意但存疑的状态：它意味着测试套件无法被他人验证，访问者也拿不到任何质量证据。

### 没有基准测试

切片调整、位图、调度器都有单元和集成测试，但没有任何测量数据。高连接数或超大文件下引擎的表现如何，没有量化答案。

### API 稳定性

模块处于 `v0.1.0`。按语义化版本，`v0.x` 允许在次版本之间引入破坏性变更。依赖它请锁版本。

## 路线

按我会做的顺序：

1. **把测试文件纳入版本库**，让 CI 真正检查东西、让测试套件可被 review。
2. **跨进程续传** —— 最大的功能缺口。
3. **限速** —— 下载库最常被要求的功能。
4. **User-Agent 选项**以及其他一些小便利。
5. **并行路径的基准测试**。

以上都不构成承诺。这页记录的是缺什么、以及为什么，不是时间表。
